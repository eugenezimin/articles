# Access to Google Cloud Virtual Machine through SSH

A practical walkthrough for establishing a secure SSH connection to a Google Compute Engine virtual machine, intended as a companion piece to the earlier article on provisioning the VM itself. The article opens with a concise but technically accurate overview of how SSH works: client and server negotiate an encrypted symmetric session cipher, use asymmetric key pairs to authenticate each side, and protect all subsequent traffic with HMAC-based integrity checks. Supported encryption algorithms (AES, ChaCha20, Blowfish) and the default TCP port 22 are covered, giving readers enough background to understand why each configuration step matters rather than just copying commands.

The bulk of the article covers local machine setup across all three major platforms. On Linux and macOS, OpenSSH is typically pre-installed; on Windows, the guide covers both the built-in SSH client (Windows 11) and third-party alternatives like PuTTY and Git Bash. Key generation with `ssh-keygen` is explained in depth, including the `-t`, `-b`, and `-C` flags and a comparison of RSA (broad compatibility, larger keys), ECDSA (elliptic curve, smaller keys at equivalent strength), and Ed25519 (modern, fastest, recommended for new setups). The article explains where generated keys are stored (`~/.ssh/`), the naming convention for public vs. private key files, and how the public key content must be placed in `~/.ssh/authorized_keys` on the remote server.

A GCP-specific section covers the platform's requirement to append a JSON object with `userName` and `expireOn` fields to the public key before pasting it into the Compute Engine metadata. The article then addresses server-side hardening — disabling password-based authentication in `sshd_config` to eliminate the attack surface for brute-force attempts — and explains why cloud providers that enable password login by default are exposing users to unnecessary risk. By the end, readers have a fully secured, key-only SSH connection to their GCP virtual machine.
