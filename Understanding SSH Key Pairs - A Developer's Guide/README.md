# Understanding SSH Key Pairs — A Developer's Guide

A developer-focused guide that goes beyond "generate a key with ssh-keygen" and explains what SSH key pairs actually are and why they work. The article begins with a clear model of the public/private key relationship: the public key is a lock you can hand to any server, the private key is the unique key that opens only your locks, and the private key never leaves your machine. This eliminates both password transmission over the network and the brute-force risk that password-based authentication carries. The article positions key pairs as the foundation of secure git operations, server access, and automated deployments — the authentication layer that most developers rely on every day without fully understanding.

The core of the article is a mathematically honest but accessible walkthrough of the three dominant key algorithms. RSA's security is grounded in the computational difficulty of factoring large numbers: the article works through a simplified but numerically correct example using small primes, showing how the public and private exponents are derived and how encryption and decryption are inverses of each other. It then explains why real RSA keys use 2048- or 4096-bit numbers — a 4096-bit number is roughly 1,234 decimal digits long — and why factoring them is infeasible with current computing. ECDSA's elliptic curve approach is presented as an alternative that achieves equivalent security with much smaller key sizes by exploiting the difficulty of the elliptic curve discrete logarithm problem. Ed25519, a modern Edwards-curve design, is shown to outperform both on speed and security and is recommended as the default for any new setup.

The practical sections cover `ssh-keygen` invocations for each algorithm, key length recommendations, the role of passphrases in protecting the private key at rest, and the naming convention for key files in `~/.ssh/`. The article also explains key fingerprints — how they are derived and why they appear during first connection to a new host — and the `authorized_keys` file format on the server side. Throughout, the emphasis is on building a mental model accurate enough that readers can make informed choices rather than cargo-culting commands from Stack Overflow.
